# Расписание ВолгГТУ — Mini App в Telegram

Приложение внутри Telegram, которое показывает расписание занятий ВолгГТУ, и
бот, который его обслуживает. Файлы расписаний берутся с
[сайта университета](https://www.vstu.ru/student/raspisaniya/zanyatiy/):
студент выбирает в настройках уровень, факультет, курс и группу — всё
остальное (скачать, разобрать шахматку, обновлять) бот делает сам.

```
сайт ВолгГТУ ─▶ .xls/.xlsx ─▶ парсер шахматки ─▶ PostgreSQL ─▶ Mini App
```

## Что умеет

**Приложение** — открывается кнопкой в боте и кнопкой меню слева от поля ввода:

* пары сразу по двум неделям (числитель/знаменатель): день, время, аудитория,
  преподаватель, даты занятий;
* переключатель **Обе недели / 1-я / 2-я**;
* режим **Реальные пары** (включается в настройках): в файле учебного отдела
  две пары иногда делят одно время и идут по очереди, в разные даты — этот
  режим оставляет в списке только те, что идут на ближайших двух неделях;
* вкладка **Календарь**: месяцы сентября–декабря, занятые дни залиты, на каждом
  кружки по числу пар с цветом по типу занятия, тап по дате — карточка дня;
* тап по паре — шторка с деталями и полным списком дат;
* **заметки к парам**: в шторке пары выбирается дата занятия и пишется
  заметка именно на неё («принести словарь», «сдать лабу»). На чипах дат с
  заметкой стоит точка, а сама заметка видна под парой в списке и в карточке
  дня. Хранится у бота, поэтому одинаково видна с телефона и с компьютера и
  переживает перезалив файла с сайта;
* **напоминание о заметке**: под ней выбирается, когда написать в чат —
  пресетом («за 1 день», «за 3 дня») или вручную календарём и колёсами часов.
  В назначенное время бот присылает пару, её время, аудиторию и текст
  заметки;
* вкладка **Настройки**: уровень образования, факультет, курс и группа.
  Курс — это конкретный файл на сайте: приложение просит бота скачать его и
  показывает, сколько внутри групп и пар и когда он обновлялся.

**Бот** — вход в приложение и уведомления: `/start` и `/app` присылают кнопку
«Открыть расписание» и поправляют кнопку меню. Расписания текстом в боте нет.

**Уведомления об изменениях** — когда учебный отдел перевыкладывает файл, бот
сравнивает новое расписание группы с прежним и пишет тем, у кого эта группа
выбрана: что добавилось, что убрали, где сменились аудитория, преподаватель,
тип занятия, время или даты («перенос 13.10 → 20.10»). Отключается в
настройках приложения.

Даты сравниваются осторожно, чтобы не слать пустых тревог: только будущие,
только прочитанные из файла (расчёт по чётности недели держится на границах
семестра, а не на расписании), и только если правила их расчёта с прошлого
импорта не менялись. Если «переехала» половина пар группы разом, это считается
пересчётом, а не правкой, и сообщение не уходит.

**Обновление** — при старте бот докачивает все недостающие файлы каталога
(7 дневных факультетов бакалавриата: ФАСТиВ, ФАТ, ФТКМ, ФТПП, ФЭУ, ФЭВТ, ХТФ —
плюс магистратура), поэтому группы видны сразу. Дальше раз в
`SCHEDULE_REFRESH_HOURS` часов сверяет каждый файл с сайтом условным запросом:
пока файл не менялся, сайт отвечает `304` без тела и весь каталог обходится за
пару секунд.

**Работа по плохой сети** — разобранное расписание хранится в `localStorage`,
поэтому открывается мгновенно и переживает обрыв связи; у сервера приложение
спрашивает только «не изменилось ли» и получает `304`. Статика несёт версию в
адресе и отдаётся сжатой, а мост Telegram лежит своей копией в `webapp/` — в
России `telegram.org` замедляют, и без копии приложение не стартовало бы.

## Стек

| слой | чем сделано |
| --- | --- |
| бот | Python 3.13, aiogram |
| веб-сервер Mini App | aiohttp, в том же процессе, что и бот |
| хранение | PostgreSQL 18, SQLAlchemy (asyncio) + asyncpg |
| парсер расписаний | xlrd (`.xls`) и openpyxl (`.xlsx`) |
| приложение | HTML/CSS/JS без сборки, Telegram Web App |
| запуск | Docker Compose + SSH-туннель до публичного HTTPS |

## Быстрый старт

Нужен Docker Desktop (на Windows — с WSL 2 и включённой виртуализацией) и токен
бота от [@BotFather](https://t.me/BotFather).

```cmd
copy .env.example .env
```

В `.env` обязательно заполнить только `BOT_TOKEN`; остальное работает как есть.
Дальше весь стек поднимается одной командой:

```cmd
docker compose up -d --build
```

| контейнер | что делает | наружу |
| --- | --- | --- |
| `schedule-db` | PostgreSQL 18, данные в томе `vstu-pgdata` | `localhost:5433` |
| `schedule-bot` | бот + веб-сервер Mini App | `localhost:7070` |
| `schedule-tunnel` | публичный HTTPS-адрес через localhost.run | — |

Таблицы создаются сами при первом запуске. Бот готов, когда `docker compose ps`
показывает у него `healthy`, а в логах есть строка «Бот запущен» — после этого
`/start` в Telegram открывает расписание.

```cmd
docker compose logs -f bot                                :: логи бота
docker compose ps                                         :: что запущено
docker exec -it schedule-db psql -U schedule -d schedule  :: консоль psql
docker compose down                                       :: остановить (данные остаются)
docker compose down -v                                    :: удалить вместе с данными
```

После правок в `bot/` или `webapp/` нужна именно пересборка
(`docker compose up -d --build bot`): код копируется внутрь образа, и
`restart` поднимет старую версию.

## Публичный адрес Mini App

Telegram открывает приложения **только по HTTPS**, поэтому `http://localhost`
не подойдёт — в стеке есть туннель. Профиль `lhr` (значение по умолчанию в
`COMPOSE_PROFILES`) поднимает SSH-реверс до localhost.run: ни домена, ни
аккаунта, ни установки.

Адрес такого туннеля меняется при каждом переподключении, поэтому он **не
прописывается руками**: туннель пишет выданный адрес в общий том `/state/url`,
бот читает его оттуда и сам переставляет кнопку меню — общую и персонально
каждому, кто уже писал боту. Поэтому `WEBAPP_URL` в `.env` остаётся пустым:
заданный явно адрес главнее файла. Посмотреть текущий:

```cmd
docker compose logs tunnel | findstr lhr.life
```

Постоянный поддомен даёт регистрация SSH-ключа на
<https://admin.localhost.run/>: ключ кладётся в `secrets/lhr_ed25519`,
контейнер подхватывает его сам. Cloudflare Tunnel как альтернатива не
поддерживается — часть российских провайдеров обрывает с ним TLS-рукопожатие.

## Переменные окружения

| переменная | назначение |
| --- | --- |
| `BOT_TOKEN` | токен бота от @BotFather |
| `COMPOSE_PROFILES` | профиль туннеля, оставить `lhr` |
| `WEBAPP_URL` | адрес приложения; пустой — брать из файла туннеля |
| `DATABASE_URL` | строка подключения; в Docker задаётся из `docker-compose.yml` |
| `SCHEDULE_REFRESH_HOURS` | как часто сверять расписания с сайтом (по умолчанию 6) |
| `SEMESTER_START`, `SEMESTER_END` | границы семестра для расчёта дат занятий |
| `WEBAPP_HOST`, `WEBAPP_PORT` | адрес веб-сервера приложения |
| `WEBAPP_ALLOW_INSECURE` | `1` — открывать приложение без подписи Telegram (см. [Разработка](#разработка)) |

## Запуск без Docker

Понадобится PostgreSQL — проще всего поднять только базу:
`docker compose up -d db`. Бот запускается модулем (именно `-m`: `bot` — пакет
с относительными импортами):

```cmd
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python -m bot.main
```

Одна команда поднимает и бота, и веб-сервер приложения. Публичный адрес всё
равно нужен, а туннель из compose смотрит внутрь своей сети — пробросьте сами:

```cmd
ssh -R 80:localhost:7070 nokey@localhost.run
```

## Разработка

Тесты парсера, дат, каталога сайта и API:

```cmd
python -m pytest tests -q
```

Разобрать файл расписания без бота и базы — печатает группы, занятия с
рассчитанными датами и предупреждения:

```cmd
python scripts\parse_preview.py "C:\Downloads\ОН_Магистратура_1 курс ФЭВТ.xls"
```

Правку вёрстки удобно смотреть в обычном браузере: `WEBAPP_ALLOW_INSECURE=1`
открывает приложение по `http://localhost:7070` без подписи Telegram. Включать
только при **остановленном туннеле** (`docker compose stop tunnel`), иначе API
без проверки подписи окажется доступен всем по публичному адресу.

## Структура проекта

```
webapp/          Mini App: index.html, app.css, app.js + копия моста Telegram
bot/
  main.py        запуск бота и веб-сервера в одном процессе
  config.py      настройки из .env
  webapp/        aiohttp: статика, /api, проверка подписи Telegram, адрес приложения
  db/            модели (groups / lessons / lesson_dates / users / schedule_changes /
                 lesson_notes …) и сессия
  parsing/       разбор шахматки: книга, сетка, роли ячеек, типы занятий, даты
  services/      каталог сайта, скачивание и импорт файлов, разница расписаний,
                 рассылка уведомлений, заметки, выборки для API
  handlers/      /start и /app
scripts/         parse_preview.py (разбор файла), tunnel.sh (туннель + адрес)
tests/           тесты парсера, дат, каталога, API и сравнения расписаний
Dockerfile       образ бота вместе с Mini App
docker-compose.yml
```

Как устроен разбор шахматки, откуда берутся даты занятий и по каким признакам
определяется лекция/лаба/практика — подробно расписано в комментариях модулей
`bot/parsing/`: `vstu_xls.py`, `dates.py`, `classify.py`.

## Ограничения

* Тип занятия в исходном файле почти нигде не подписан и вычисляется по
  структуре расписания — редкие ошибки возможны.
* Опечатки в файле учебного отдела бот не исправляет, но отмечает
  предупреждением: их видно в строке «Курс» на экране настроек.
* Повторный импорт того же файла **перезаписывает** занятия затронутых групп.
* Каталог сайта разбирается регулярными выражениями: если страницу расписаний
  переверстают, список файлов придётся поправить в `bot/services/vstu_site.py`.
* Поддерживается только обычная сетка учебных занятий — расписания сессии и
  практик отдельными форматами не разбираются.
* Аспирантура и вечерние факультеты в каталог не попадают.
