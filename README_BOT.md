# Телеграм-бот «Расписание ВолгГТУ»

Бот принимает ссылку на файл расписания ВолгГТУ (`.xls`), разбирает его,
раскладывает **все группы из файла** по базе с делением на **бакалавриат /
магистратуру** и показывает расписание по мотивам дизайна: список пар по двум
неделям и календарь с отмеченными занятыми днями.

```
Ссылка .xls  ─▶  парсер шахматки  ─▶  PostgreSQL  ─▶  экраны бота
                                      groups (bachelor|master)
                                      lessons + lesson_dates
```

## Что умеет

* **`/import <ссылка>`** — скачивает `.xls`, разбирает и сохраняет все группы файла.
  Можно просто прислать файл `.xls` в чат — он импортируется так же.
  Уровень (бакалавриат/магистратура), факультет и курс определяются из шапки
  файла и его имени.
* **`/start`, `/schedule`** — экран «Расписание»: обе недели (числитель/знаменатель),
  дни, пары со временем, аудиторией, преподавателем и датами занятий.
* Кнопка с названием группы вверху — **смена группы**; группы сгруппированы по
  бакалавриату и магистратуре.
* Переключатель **Обе недели / 1-я / 2-я**.
* Вкладка **Календарь** — месяц с кружками на занятых днях (один кружок = одна
  пара, цвет = тип занятия), тап по дате открывает карточку дня.
* Тап по паре — карточка с временем, аудиторией, преподавателем и полным списком дат.

## Установка (Windows, cmd)

```cmd
cd /d C:\путь\к\проекту
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env
```

Дальше открыть `.env` и заполнить:

* `BOT_TOKEN` — токен от @BotFather;
* `DATABASE_URL` — строка подключения к PostgreSQL;
* `ADMIN_IDS` — ваш Telegram id (узнать можно у @userinfobot). Если оставить
  пустым, `/import` будет доступен всем — удобно при настройке, но на публичном
  боте заполните.

### PostgreSQL в Docker (рекомендуется)

В проекте есть `docker-compose.yml` на образе `postgres:latest`:

```cmd
docker compose up -d
docker compose ps
```

База, пользователь и пароль — `schedule` / `schedule` / `schedule`, данные
лежат в именованном томе `vstu-pgdata` и переживают перезапуск контейнера.
Строка подключения для `.env`:

```
DATABASE_URL=postgresql+asyncpg://schedule:schedule@localhost:5432/schedule
```

Полезные команды:

```cmd
docker compose logs -f db                                   :: логи
docker compose stop                                         :: остановить
docker compose start                                        :: запустить снова
docker exec -it vstu-postgres psql -U schedule -d schedule  :: консоль psql
docker compose down                                         :: удалить контейнер (том остаётся)
docker compose down -v                                      :: удалить вместе с данными
```

То же самое без compose, одной командой:

```cmd
docker run -d --name vstu-postgres --restart unless-stopped -e POSTGRES_USER=schedule -e POSTGRES_PASSWORD=schedule -e POSTGRES_DB=schedule -p 5432:5432 -v vstu-pgdata:/var/lib/postgresql/data postgres:latest
```

Если порт 5432 уже занят локально установленным PostgreSQL, поменяйте
проброс на `5433:5432` и порт в `DATABASE_URL`.

### PostgreSQL без Docker

Если сервер уже установлен, создайте базу и пользователя:

```cmd
psql -U postgres -c "CREATE USER schedule WITH PASSWORD 'schedule';"
psql -U postgres -c "CREATE DATABASE schedule OWNER schedule;"
```

Таблицы бот создаёт сам при первом запуске — миграции не нужны.

## Как устроен разбор файла

Формат «шахматки» учебного отдела:

* строка заголовка — названия групп, по 4 колонки на группу;
* колонка 0 — дни недели, каждый день занимает 18 строк (6 пар × 3 строки);
* дни идут **дважды**: сначала НЕДЕЛЯ 1 (числитель), потом НЕДЕЛЯ 2 (знаменатель);
* внутри пары сверху вниз: НАЗВАНИЕ ПРЕДМЕТА → строка-заметка (конкретные даты,
  «занятия с 16.09», «лаб.», «9-12ч») → преподаватель и аудитория;
* занятие на 4 часа занимает две пары подряд — время считается как объединение;
* лекция для нескольких групп объединена по колонкам и попадает в каждую из них.

Даты занятий раскрываются так:

1. перечислены конкретные даты в файле → берутся как есть;
2. «занятия с ДД.ММ» → обычное чередование, но не раньше указанной даты;
3. иначе — через неделю, по чётности своего блока. Предмет, идущий каждую
   неделю, в исходнике стоит в обоих блоках, поэтому «еженедельно» получается
   объединением двух записей.

Границы семестра задаются в `.env` (`SEMESTER_START`, `SEMESTER_END`).

## Известные ограничения

* **Тип занятия** (лекция / семинар / лаба) в исходном файле размечен не везде —
  распознаются только явные пометки «(лекция)» и «лаб.». Остальные пары
  показываются нейтральным ⚪️ «тип не указан», чтобы не выдумывать данные.
* Файл может содержать опечатки (в проверенном файле у САПР-1.4 в пятницу стоит
  `13.10` вместо `13.11`). Такие места бот не исправляет, но выводит
  предупреждение после импорта — их видно в отчёте `/import`.
* Повторный импорт того же файла **перезаписывает** занятия затронутых групп.
* Расписания сессии/практик отдельными форматами не поддерживаются — только
  обычная сетка учебных занятий.

## Структура проекта

```
bot/
  main.py                 запуск бота (long polling)
  config.py               настройки из .env
  db/models.py            groups / lessons / lesson_dates / users / import_logs
  db/session.py           асинхронный движок и создание таблиц
  parsing/grid.py         разворачивание объединённых ячеек xls
  parsing/classify.py     распознавание ролей ячеек и типов занятий
  parsing/vstu_xls.py     разбор шахматки в список занятий
  parsing/dates.py        расчёт конкретных дат занятий
  services/import_service.py     скачивание, разбор, запись в БД
  services/schedule_service.py   выборки для экранов
  handlers/schedule.py    экраны: расписание, календарь, карточки
  handlers/admin_import.py  /import и приём файла
  keyboards/navigation.py inline-клавиатуры
  utils/formatting.py     отрисовка экранов
scripts/parse_preview.py  разбор файла без бота
tests/                    тесты парсера и дат
```
