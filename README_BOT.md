# Расписание ВолгГТУ — приложение в Telegram

Mini App внутри Telegram по макету из Claude Design плюс бот, который его
обслуживает. Расписание берётся с сайта университета: во вкладке «Настройки»
выбирают уровень, факультет и курс — это конкретный файл на
[странице расписаний](https://www.vstu.ru/student/raspisaniya/zanyatiy/), —
бот скачивает его, разбирает шахматку и дальше обновляет сам.

```
сайт ВолгГТУ ─▶ каталог ─▶ выбранный .xls/.xlsx ─▶ парсер шахматки ─▶ PostgreSQL ─▶ Mini App
 7 факультетов   настройки   скачивание по кругу                      groups        (webapp/)
 + магистратура  приложения  раз в SCHEDULE_REFRESH_HOURS часов        lessons + lesson_dates
```

Берутся только дневные факультеты бакалавриата (ФАСТиВ, ФАТ, ФТКМ, ФТПП, ФЭУ,
ФЭВТ, ХТФ) и общая страница магистратуры. Аспирантура и вечерние факультеты в
каталог не попадают.

## Что умеет

**Приложение (Mini App)** — открывается кнопкой в боте и кнопкой меню слева от
поля ввода:

* список пар сразу по двум неделям (числитель/знаменатель), дни, время,
  аудитория, преподаватель и даты занятий;
* переключатель **Обе недели / 1-я / 2-я**;
* вкладка **Календарь**: месяцы сентябрь–декабрь, занятые дни залиты, на каждом
  кружки по числу пар с цветом по типу занятия, тап по дате — карточка дня;
* тап по паре — шторка со временем, аудиторией, преподавателем и полным
  списком дат;
* вкладка **Настройки**: уровень образования, факультет, курс и группа.
  Выбранный курс — это файл на сайте: приложение просит бота его скачать,
  показывает, сколько в нём групп и пар и когда он обновлялся, а затем даёт
  выбрать свою группу.

**Бот** — только вход в приложение: **`/start`** и **`/app`** присылают кнопку
«Открыть расписание» и поправляют кнопку меню слева от поля ввода. Расписания
текстом в боте нет, загрузка файлов вручную тоже убрана — всё делается в
приложении.

**Обновление**: при старте бот докачивает все файлы каталога, которых ещё нет
в базе, — поэтому в настройках группы любого факультета видны сразу. Дальше
раз в `SCHEDULE_REFRESH_HOURS` часов (по умолчанию 6) он сверяет каждый файл с
сайтом условным запросом (`If-None-Match` / `If-Modified-Since`): пока файл не
менялся, сайт отвечает `304` без тела, и весь каталог обходится за пару секунд
и несколько килобайт. Изменившийся файл перекачивается и перезаливается;
новые группы из него добавляются в таблицу `groups`, старые не удаляются.

**Трафик приложения**: адреса `app.js`, `app.css` и моста Telegram несут
версию (`?v=…`, по содержимому файлов) и отдаются с `immutable` на год —
повторное открытие их не качает. В образе Docker рядом со статикой лежат
сжатые копии (`.gz`), и aiohttp отдаёт их сам: мост Telegram худеет со 116 КБ
до 18. JSON и страница сжимаются на лету. Без версии в адресе встроенный
браузер Telegram (особенно iPhone) брал старые скрипты из кэша, не спрашивая
сервер, а через узкий прокси Telegram Desktop несжатый мост приходил
кусками (серии `206`) и не докачивался.

## Настройка (Windows, cmd)

```cmd
cd /d C:\путь\к\проекту
copy .env.example .env
```

Дальше открыть `.env` и заполнить:

* `BOT_TOKEN` — токен от @BotFather;
* `COMPOSE_PROFILES` — оставить `lhr`: туннель localhost.run, ни домена, ни
  аккаунта (подробнее в «Адрес Mini App»);
* `WEBAPP_URL` — оставить пустым: для `lhr` адрес выдаётся при подключении и
  бот читает его сам;
* `DATABASE_URL` — нужен только для запуска без Docker; в контейнере он задаётся
  из `docker-compose.yml`;
* `SCHEDULE_REFRESH_HOURS` — как часто сверять расписания с сайтом
  (по умолчанию 6 часов).

Дальше два пути: всё в Docker (проще) или вручную в виртуальном окружении.

## Запуск в Docker (рекомендуется)

### Установка Docker на Windows 10/11

Нужен Docker Desktop, а ему — WSL 2. Виртуализация в BIOS должна быть
включена (диспетчер задач → «Производительность» → «ЦП» → «Виртуализация:
включено»). Оба шага — из PowerShell **от администратора**, между ними
перезагрузка:

```powershell
wsl --install --no-distribution
```

После перезагрузки:

```powershell
winget install -e --id Docker.DockerDesktop --accept-package-agreements --accept-source-agreements
```

Запустить Docker Desktop, принять условия (для личного использования
бесплатно) и дождаться статуса «Engine running». В настройках должно стоять
«Use the WSL 2 based engine» — по умолчанию так и есть. Проверка из любого
терминала:

```cmd
docker compose version
```

### Запуск стека

Весь стек — база, бот вместе с приложением и туннель — поднимается одной командой:

```cmd
docker compose up -d --build
```

Всегда поднимаются два контейнера:

| контейнер | что делает | наружу |
| --- | --- | --- |
| `schedule-db` | PostgreSQL 18, данные в томе `vstu-pgdata` | `localhost:5433` |
| `schedule-bot` | бот + веб-сервер Mini App (`webapp/` в том же процессе) | `localhost:7070` |

и туннель до публичного адреса:

| профиль | контейнер | что делает |
| --- | --- | --- |
| `lhr` | `schedule-tunnel` | localhost.run: временный адрес, ни домена, ни аккаунта |

Внутри сети compose база зовётся `db:5432`, и `DATABASE_URL` для контейнера
задан прямо в `docker-compose.yml` — он перекрывает значение из `.env`, чтобы
хостовые инструменты (`scripts/parse_preview.py`, `psql`) продолжали ходить на
`localhost:5433`. Таблицы создаются сами при первом запуске.

Полезные команды:

```cmd
docker compose logs -f bot                                :: логи бота
docker compose ps                                         :: что запущено
docker exec -it schedule-db psql -U schedule -d schedule  :: консоль psql
docker compose restart bot                                :: перезапустить бота
docker compose down                                       :: остановить (том остаётся)
docker compose down -v                                    :: удалить вместе с данными
```

### Адрес Mini App

Telegram открывает приложения **только по HTTPS**, поэтому `http://localhost`
не подойдёт: нужен туннель до публичного адреса. Вариантов два, выбор —
`COMPOSE_PROFILES=lhr` в `.env`.

#### `lhr` — localhost.run, без домена

SSH-реверс до localhost.run: ни аккаунта, ни установки. В `.env`:

```
COMPOSE_PROFILES=lhr
WEBAPP_URL=
```

Адрес быстрого туннеля меняется при каждом переподключении, поэтому он **не
прописывается руками**: `scripts/tunnel.sh` записывает выданный адрес в общий
том (`/state/url`), а бот читает оттуда на каждое построение кнопки. Именно
поэтому `WEBAPP_URL` должен быть пустым: заданный явно адрес главнее файла.
Посмотреть текущий адрес:

```cmd
docker compose logs tunnel | findstr lhr.life
```

Момент смены видно в логах бота:

```
INFO __main__: Кнопка меню ведёт на https://e7cbd743fc8699.lhr.life
```

Уже открытое у пользователя окно приложения после смены адреса перестаёт
отвечать. Постоянный поддомен даёт регистрация SSH-ключа на
<https://admin.localhost.run/> (без регистрации ключ отвергается —
`Permission denied (publickey)`): ключ кладётся в `secrets/lhr_ed25519`,
контейнер подхватывает его сам.

#### Кнопка меню

Кнопку меню слева от поля ввода бот ставит сам и держит на актуальном адресе:
раз в несколько секунд сверяется с адресом и при его смене
переставляет кнопку — общую и персонально каждому, кто уже писал боту (их
Telegram id есть в таблице `users`). Поэтому после перезапуска бота или обрыва
туннеля ничего отправлять не нужно: кнопка «Расписание» начинает работать сама
за несколько секунд. `/start` тоже присылает кнопку «📅 Открыть расписание» —
она строится заново на каждый вызов.

Персональная кнопка чата главнее общей, поэтому обновлять нужно именно её:
пока бот переставлял одну общую, пользователь продолжал открывать свою,
оставшуюся на адресе прошлого туннеля, и видел заглушку `no tunnel here :(`.
Общая кнопка применяется на стороне Telegram с задержкой около минуты — это
влияет только на тех, кто ещё ни разу не писал боту.

В BotFather ничего настраивать не нужно; если хотите постоянную кнопку с
именем приложения — `/newapp` у @BotFather.

### Долго грузится и пишет «Откройте приложение через Telegram»

Приложение подключает мост Telegram (`window.Telegram.WebApp`) скриптом
`https://telegram.org/js/telegram-web-app.js`. Встроенный браузер Telegram
качает его обычной сетью устройства, не через прокси мессенджера, а
`telegram.org` в России с 2025 года замедляют: у части операторов скрипт
грузится десятки секунд или не грузится вовсе. Тогда приложение стартует без
моста, запрос уходит без подписи Telegram, и сервер отвечает 401 —
на экране это «Не удалось загрузить». Признак в логе бота: `GET /api/schedule
... 401` через 20–30 секунд после `GET /`.

Поэтому приложение отдаёт **свою копию скрипта** — `webapp/telegram-web-app.js`,
подключается как `/static/telegram-web-app.js`, и от доступности `telegram.org`
не зависит. Telegram это допускает; копию стоит обновлять раз в несколько
месяцев, чтобы не отстать от новых возможностей платформы:

```cmd
curl -o webapp\telegram-web-app.js https://telegram.org/js/telegram-web-app.js
docker compose up -d --build
```

Заодно скрипт подключается в конце страницы, а шрифты Google не блокируют
отрисовку — «Загружаем расписание…» показывается сразу. Сообщение об ошибке
различает три случая: скрипт Telegram не загрузился, приложение открыто в
обычном браузере, отказ сервера. Сервер отдаёт страницу и статику с
`Cache-Control: no-cache`, поэтому после пересборки клиенты Telegram сразу
видят новую версию, а не закэшированную.

### Отладка в обычном браузере

```
WEBAPP_ALLOW_INSECURE=1
```

С этим флагом приложение открывается по `http://localhost:7070` без подписи
Telegram — удобно править вёрстку. Включать только при **остановленном
туннеле** (`docker compose stop tunnel`,
смотря какой профиль): иначе API без проверки подписи
окажется доступен любому, кто знает публичный адрес. На рабочем боте — `0`.

## Запуск без Docker

Понадобится PostgreSQL. Проще всего поднять только базу:

```cmd
docker compose up -d db
```

Либо, если сервер уже установлен, создать базу и пользователя вручную:

```cmd
psql -U postgres -c "CREATE USER schedule WITH PASSWORD 'schedule';"
psql -U postgres -c "CREATE DATABASE schedule OWNER schedule;"
```

Строка подключения для `.env` (порт 5433 — как в `docker-compose.yml`):

```
DATABASE_URL=postgresql+asyncpg://schedule:schedule@localhost:5433/schedule
```

Дальше — виртуальное окружение и запуск модулем (именно `-m`: `bot` — пакет с
относительными импортами, `python bot\main.py` упадёт):

```cmd
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python -m bot.main
```

Одна команда поднимает и бота, и веб-сервер приложения (порт из `WEBAPP_PORT`).
Публичный адрес всё равно нужен — можно поднять только туннель из compose
(`docker compose up -d tunnel`), но он смотрит на `bot:7070` внутри сети
compose, поэтому для хостового запуска пробросьте туннель сами:

```cmd
ssh -R 80:localhost:7070 nokey@localhost.run
```

## Как устроен разбор файла

Формат «шахматки» учебного отдела:

* строка заголовка — названия групп, по 4 колонки на группу;
* колонки с числами месяцев — слева от дней недели (бакалавриат) либо между
  днём и номерами пар (магистратура); ищутся по заголовкам месяцев левее
  первой группы;
* дни недели — в колонке 0 (магистратура) либо в колонке 4 (бакалавриат, слева
  от них четыре колонки с числами месяцев); нужная колонка ищется по числу
  попаданий в список дней. Каждый день занимает 18 строк (6 пар × 3 строки);
* дни идут **дважды**: сначала НЕДЕЛЯ 1 (числитель), потом НЕДЕЛЯ 2 (знаменатель);
* внутри пары сверху вниз: НАЗВАНИЕ ПРЕДМЕТА → строка-заметка (конкретные даты,
  «занятия с 16.09», «лаб.», «9-12ч») → преподаватель и аудитория;
* занятие на 4 часа занимает две пары подряд — время считается как объединение;
* лекция для нескольких групп объединена по колонкам и попадает в каждую из них.

Даты занятий берутся из самого файла. Слева от сетки стоят колонки
«Сентябрь … Декабрь», и внутри блока каждого дня под ними перечислены числа —
даты, когда этот день с этой чётностью недели действительно идёт. Учебный
отдел уже учёл в них и праздники, и то, что занятия кончаются раньше конца
декабря. Порядок источников:

1. перечислены конкретные даты у самой пары → берутся как есть;
2. иначе даты дня из колонок с числами месяцев;
3. «занятия с ДД.ММ» → то же самое, но не раньше указанной даты;
4. если колонок с числами в файле нет — через неделю, по чётности своего
   блока. Это страховка: из 516 блоков дней в расписаниях семестра такой
   расчёт расходится с файлом в 147, в основном дотягивая занятия до
   28–31 декабря, когда пар уже нет. Предмет, идущий каждую неделю, в
   исходнике стоит в обоих блоках, поэтому «еженедельно» получается
   объединением двух записей.

Границы семестра задаются в `.env` (`SEMESTER_START`, `SEMESTER_END`).

## Как определяется тип занятия

В исходном файле тип почти нигде не подписан, зато он однозначно читается из
самой сетки. Правила применяются в этом порядке:

1. **Лекция по пометке** — в блоке прямо написано «(лекция)». Пометка ищется
   только в скобках, иначе под неё попали бы названия предметов вроде
   «ПРОИЗВОДСТВЕННАЯ ПРАКТИКА» или «СПЕЦИАЛЬНЫЙ ФИЗИЧЕСКИЙ ПРАКТИКУМ».
2. **Лекция** — одна и та же пара стоит одновременно у нескольких групп.
   Опознаётся двумя способами: ячейка предмета объединена по колонкам
   нескольких групп, либо у разных групп совпали неделя, день, пара, предмет,
   аудитория **и даты занятий**.

   Даты в сравнении обязательны: две группы часто ходят в одну аудиторию к
   одному преподавателю в одно и то же время, но по очереди — через неделю
   друг от друга. Это лабы по подгруппам, а не общая лекция, и различаются они
   только перечнем дат. Преподаватель, наоборот, в сравнении не участвует: его
   фамилию в файле пишут по-разному («Харланов А.В» и «Харламов А.В.»).
3. **Практика** — пара на один слот (2 академических часа), либо пара любой
   длины, идущая раз в две недели. Раз в две недели — это занятие без перечня
   дат (оно повторяется по чётности своего блока), «занятия с 16.09», либо
   перечисленные даты с шагом в две недели. Так стоит, например, «проф. ин-яз»:
   4 часа, но через неделю.
4. **Лаба** — всё остальное: 4 академических часа реже, чем раз в две недели
   (обычно раз в месяц, по перечисленным датам).

Правила покрывают все случаи, поэтому типа «занятие не определено» больше нет.
На проверенном файле выходит 34 лекции, 41 лаба и 37 практик из 112 пар,
из них 6 лекций распознаны по пометке «(лекция)».

Правила сверены с расписанием САПР-1.4, размеченным по типам вручную: из
15 пар группы совпали 13, а два расхождения оказались ошибками разметки —
«Системы обработки больших данных» во вторник идёт только у САПР-1.4 (это
лаба, не лекция), а «Технологии анализа данных» в пятницу 7-8 стоят
одновременно у САПР-1.4 и ЭВМ-1.2 в одной аудитории (это лекция, не лаба).

### Пары, стоящие не в своей строке

Иногда две пары претендуют на одни и те же часы (идут в разные недели), и
учебный отдел рисует вторую ниже — в свободной клетке, — а настоящее время
дописывает внутрь блока: «1-4ч», «5-8 ч», «9-12ч». Такая пометка главнее
позиции блока: часы 1-2 — это первая пара, 3-4 — вторая и так далее, поэтому
время занятия считается из неё, а не из строки, где блок нарисован. Каждый
такой перенос отмечен предупреждением при загрузке. В проверенном файле
так стоят 14 пар из 112. После переноса пары иногда попадают на одно время
внутри группы, но их даты не пересекаются — именно поэтому учебный отдел и
рисует вторую пару в свободной клетке.

## Известные ограничения

* **Тип занятия** в файле размечен лишь местами: явно подписаны только
  «(лекция)» и «лаб.». Пометка «(лекция)» учитывается и главнее всего
  остального, у прочих пар тип берётся из структуры расписания
  (см. «Как определяется тип занятия»).
* Файл может содержать опечатки (в проверенном файле у САПР-1.4 в пятницу стоит
  `13.10` вместо `13.11`). Такие места бот не исправляет, но отмечает
  предупреждением — их видно в строке «Курс» на экране настроек.
* Повторный импорт того же файла **перезаписывает** занятия затронутых групп.
* Каталог сайта разбирается регулярными выражениями: если учебный отдел
  переверстает страницу расписаний, список файлов придётся поправить в
  `services/vstu_site.py`.
* Расписания сессии/практик отдельными форматами не поддерживаются — только
  обычная сетка учебных занятий.
